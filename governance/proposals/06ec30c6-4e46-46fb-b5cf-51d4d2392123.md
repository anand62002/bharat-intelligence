## Abstract

LLM-based agents can act on behalf of a user to access cloud services, call tools, or invoke agents. At session start, the agent's permissions are set but remain static, and each request is evaluated independently, without considering prior actions. Within its permissions, an agent may act contrary to the delegated task, combine individually permitted actions into a prohibited outcome, or delegate authority to a sub-agent without limiting it. A prompt injection poses a risk only if the agent has authority to perform such actions; this is therefore a problem of authorization architecture, not just the model. ## Proposed Change

Add a session-scoped APC tracker in orchestrator/langgraph_flow.py that maintains per-agent cumulative action budgets (API calls, token spend, data fetch counts) and prohibited action combinations (e.g., sentiment agent cannot trigger institutional bulk-deal purchases within same session). Implement six authorization checks before each agent invocation: scope verification, budget enforcement, composition closure against prior actions, delegation depth limit (max 2 levels for sub-agent calls), blast radius calculation, and session state persistence to Supabase. Each agent returns an 'actions_taken' field; orchestrator validates against APC state before accepting results.
