## Abstract

Abstract: Retrieval-augmented generation services over mutable enterprise documents repeatedly execute semantically equivalent analysis requests. Answer reuse can remove GPU-bound generation work, yet response caches require dependency consistency when filings, evidence chunks, and tool outputs change. FinCacheServe treats each generated answer as a serving object indexed by enterprise intent and guarded by document versions, evidence fingerprints, tool fingerprints, model identity, and decoding configuration. A vLLM implementation evaluates SEC-derived financial-document workloads with Qwen2.5 models. ## Proposed Change

Add a dependency-aware cache layer in `agents/historical_rag.py` that indexes pgvector query results by (stock_symbol, query_embedding_hash, document_version_hash, model_id). Before executing similarity search, check cache with composite key; on hit, verify document versions haven't changed via Supabase metadata timestamps. Store cached results with their source document IDs and timestamps to enable invalidation when new earnings/filings are ingested.
