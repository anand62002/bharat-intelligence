## Abstract

Introduces a point-in-time RAG framework for financial question answering using frozen (non-fine-tuned) LLMs, with an adaptive retrieval mechanism informed by real market feedback signals to prevent lookahead bias. Benchmarks against FinDER, FinAgentBench, and Multi-FinRAG datasets, demonstrating superior temporal consistency and reduced hallucination in earnings analysis tasks.

## Proposed Change

In `agents/historical_rag.py`, modify the `retrieve_similar_context` function to enforce point-in-time retrieval by adding a `as_of_date` parameter that filters the pgvector similarity search to only return embeddings with a `recorded_at` timestamp strictly less than the query date. Concretely, add a SQL WHERE clause (`WHERE recorded_at < as_of_date`) to the existing `match_documents` Supabase RPC call, and tag each stored embedding at ingest time with its `data_as_of` date (not ingestion date) so lookahead bias from future earnings, bulk deals, or FII flow data cannot contaminate historical similarity matches. Additionally, add a `market_feedback_score` column to the `rag_documents` table that is updated weekly by `performance_tracker` (using outcome-vs-price accuracy delta) and incorporate this score as a re-ranking multiplier on the cosine similarity results, mirroring the paper's adaptive retrieval mechanism.
