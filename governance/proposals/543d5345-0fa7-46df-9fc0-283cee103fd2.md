## Abstract

arXiv:2606.20047v1 Announce Type: new 
Abstract: Conversational and tool-using LLM agents operate over a context window that fills from several directions simultaneously. As a session proceeds, the agent accumulates user and assistant turns, entries drawn from a persistent memory store, and often largest of all, the verbatim outputs of tool calls such as file reads, search results, and API responses. Once the cumulative context exceeds the model's token budget, the framework must decide what to keep.

## Proposed Change

Implement submodular context selection in orchestrator/synthesis.py's prepare_context_for_llm() function. Replace the current recency-based truncation (keeping last N agent outputs when token budget is exceeded) with a greedy submodular maximization that scores each agent's output by (relevance_to_query × information_gain × 1/token_cost). Use cosine similarity between query embedding and agent output embedding for relevance, and track which data sources are already represented to maximize diversity and avoid redundant institutional/macro facts when budget is tight.
