## Abstract

arXiv:2609.03340v1 Announce Type: new 
Abstract: Distributed LLM-agent teams can read the latest shared facts and still act on an obsolete plan. A planner may derive an action from requirement $r_3$, another agent may commit $r_4$, and an executor may receive $r_4$ without replacing the plan derived from $r_3$. We call this \emph{stale-plan execution}: state freshness does not establish that the plan authorizing an action remains valid. We introduce PlanFence, a dependency-scoped action-validation protocol. Plans cite the exact public records they used, and an executor validates only the records that can affect the pending external action, replanning once or blocking when validation is incomplete. ## Proposed Change

Add dependency-scoped validation to orchestrator/langgraph_synthesizer.py. Before executing any external action (e.g., generating final BUY/SELL signals or writing to Supabase), record which agent signals and their versions were used in the synthesis plan. If any cited agent (technical, fundamental, sentiment, etc.) updates its signal between plan creation and execution, re-synthesize only if the updated agent was a dependency for the pending action. This prevents acting on stale multi-agent consensus when one critical input (e.g., technical RSI crosses threshold) invalidates the original reasoning.
