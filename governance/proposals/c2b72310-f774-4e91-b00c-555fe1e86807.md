## Abstract

Existing evaluations often reduce agent failures to system-level outcomes, obscuring where the fault originated and which intervention would improve the agent system. This creates a repair-assignment problem: the same visible failure may call for model post-training, harness engineering, environment redesign, or benchmark repair depending on its source. Because agent behavior emerges from interactions among models, harnesses, users, tools, memory, and environments, outcome-level labels are often insufficient for improvement. ## Proposed Change

Add interaction-level failure tracking to orchestrator.py by instrumenting each agent handoff with a FailureLocalizer class that records (source_component, target_component, interaction_type, fault_side) tuples. When synthesis produces low-confidence signals (score <40) or conflicting agent outputs (BUY vs SELL delta >60), log the interaction chain and assign fault_side using heuristics: model-side if agent detail contains empty/null fields, harness-side if data_source fetch fails, environment-side if external API timeouts occur. Store failure tuples in new Supabase table `interaction_failures` with columns (timestamp, stock_symbol, agent_chain_json, fault_localization_json, outcome_label) to enable weekly root-cause analysis instead of opaque system-level metrics.
