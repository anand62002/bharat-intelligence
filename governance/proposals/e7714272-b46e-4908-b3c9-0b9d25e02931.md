## Abstract

arXiv:2605.26302v1 Announce Type: new 
Abstract: Long-lived AI agents are increasingly deployed as persistent operational systems, yet they are still evaluated like freshly initialized models. Day-one benchmarks miss a basic systems question: how long does an agent remain reliable after deployment? Even when model weights are frozen, an agent's effective state keeps changing as it compresses interaction history, retrieves from a growing memory store, revises facts after updates, and undergoes routine maintenance. Reliability therefore becomes a lifespan property of the full agent harness, not only a snapshot property of the base model. ## Proposed Change

Add a lifespan health monitor to agents/historical_rag.py that tracks retrieval quality degradation over time. Implement a weekly diagnostic that measures (1) embedding drift between new queries and stored vectors, (2) retrieval precision@5 on 20 known good queries with ground-truth answers, and (3) vector store size growth rate. When precision drops below 0.7 or drift exceeds 15%, trigger automated pgvector VACUUM and re-embed the oldest 10% of entries using current OpenAI model, then log the event to a new supabase table 'agent_health_log' with fields: agent_name, metric_type, value, threshold, remediation_action, timestamp.
