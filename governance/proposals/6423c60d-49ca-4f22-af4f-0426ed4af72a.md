## Abstract

arXiv:2610.24659v1 Announce Type: new 
Abstract: Document preprocessing choices can substantially affect retrieval in Retrieval-Augmented Generation (RAG) pipelines, yet they are often selected heuristically and are difficult to compare under consistent conditions. We present RAGit, an open-source experimentation workbench for the systematic and reproducible evaluation of document preprocessing choices through downstream retrieval. RAGit represents parsing, chunking, indexing, retrieval, and evaluation as configurable experimental stages, enabling controlled comparisons while the remaining downstream settings are kept fixed. Refactor agents/historical_rag.py to implement RAGit-inspired preprocessing experimentation by adding a PreprocessingConfig class that parameterizes chunking strategy (fixed-size vs semantic), chunk size (512/1024/2048 tokens), overlap percentage (0/10/20%), and parser type (plain/markdown-aware). Modify the embed_historical_data() function to accept a config parameter and store preprocessing metadata in Supabase alongside embeddings. Add a weekly A/B test function evaluate_preprocessing_configs() that runs retrieval queries with different configs against the same 50 benchmark stock queries (e.g., 'Reliance Q4 earnings impact', 'IT sector FII flows 2024') and measures retrieval@5 accuracy by comparing retrieved chunks to manually labeled ground-truth sources.
