## Abstract

arXiv:2611.24845v1 Announce Type: cross 
Abstract: Existing AI agents can retrieve information, call tools, run experiments, and produce multi-step outputs. Yet most are built around relatively static workflows and struggle to preserve reliable state as the environment changes. Financial trading makes this limitation especially consequential: prices, news, market conditions, portfolio positions, and available capital evolve continuously. A result is useful only when it remains tied to the correct time, data snapshot, and execution context. ## Proposed Change

Add a lightweight result provenance envelope to the base agent return structure in agents/base.py by introducing a ResultContext dataclass that wraps each agent's existing output dict with: snapshot_timestamp (UTC ISO-8601 when data was fetched), data_freshness_seconds (age of oldest source datum), run_id (uuid4 per orchestration cycle), and source_hash (SHA-256 of serialised detail dict). Modify the LangGraph orchestrator in orchestrator/daily_run.py to attach this envelope before passing agent outputs to Claude Sonnet synthesis, and update the hallucination_detector in governance/hallucination_detector.py to cross-check the snapshot_timestamp against the synthesis timestamp so claims about price/signal are invalidated if data is stale beyond a configurable threshold (default 3600s). This directly addresses the paper's core finding that results lose validity when detached from their temporal and data context, preventing the orchestrator from synthesising a BUY signal derived from yesterday's FII flow data against today's price.
