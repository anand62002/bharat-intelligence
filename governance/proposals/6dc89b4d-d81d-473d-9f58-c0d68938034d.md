## Proposed Change

In `governance/fact_checker.py`, modify the `verify_claims` function to replace the current single 'Verify' prompt style (which asks the model to check retrieved context AND prioritize it) with a two-stage approach: first run an 'Adversarial-Aware' prompt that warns the LLM that retrieved passages (from RSS feeds, Screener.in, NSE/BSE data) may be stale, misleading, or in conflict with its training knowledge, and explicitly instructs the model to flag conflicts rather than blindly adopting passage content; second, only escalate to passage-priority mode when the retrieved data is post-training-cutoff (detected via timestamp comparison against a configurable KNOWLEDGE_CUTOFF_DATE constant). This directly addresses the FutureBench finding that 'Verify'-style prompts cause false-answer adoption on pre-cutoff events by displacing correct model knowledge, while Adversarial-Aware restores 82.5-98.9% of displaced correct answers.
