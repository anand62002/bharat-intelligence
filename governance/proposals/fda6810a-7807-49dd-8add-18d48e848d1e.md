## Abstract

arXiv:2608.16891v1 Announce Type: new 
Abstract: Agentic AI systems request tool actions that can modify files, send messages, launch jobs, or change workflow state. This shifts the safety problem from harmful text generation to harmful operational side effects. Prompt-level governance can shape model behavior, but it does not create an execution boundary. We introduce Aegis, a runtime governance system that treats model outputs as action proposals and mediates them through a trusted decision layer before tool execution. The model proposes; the trusted runtime decides. Aegis evaluates proposals against active policy state, resolves provenance server-side, fails closed under uncertainty, and routes selected cases through Senate-style settlement, a quorum- based non-unilateral authorization 

## Proposed Change

Add a runtime action governance layer in orchestrator/langraph_workflow.py that wraps all agent tool executions (yfinance API calls, Screener.in scrapes, NSE bulk deal fetches, Supabase writes) in an ActionProposal class. Before executing any external call or database write, validate the proposal against a policy config (agent_policies.yaml) defining allowed endpoints, rate limits, and data mutation boundaries. Implement fail-closed execution: if policy validation fails or times out, log the blocked action to Supabase governance_audit table and return a safe fallback (cached data or HOLD signal) instead of propagating errors or allowing unchecked tool use.
