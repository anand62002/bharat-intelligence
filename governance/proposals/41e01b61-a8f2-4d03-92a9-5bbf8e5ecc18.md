## Abstract

LLM agents answer questions by calling APIs and trusting the results. An API can fail silently. It ignores part of a request, such as a misnamed filter, yet returns HTTP 200 and a plausible but wrong result. Current fixes, such as checklists, reviewer models and LLM judges, ask the model to catch it. But models often see the problem and answer anyway. We present SilentGuard, which moves the decision from the model to the harness running tool calls. It tests each result against invariants that any correct API must satisfy and withholds values that break one. We find silent failures in 11 of 15 public research APIs, with counts inflated up to 691 times. Current fixes leave over 70% of answers wrong, and agents report 77.4% of counts a judge flags. ## Proposed Change

Create a new `harness/api_invariant_guard.py` module implementing a decorator `@enforce_invariants` that wraps every agent's external API call (yfinance, NSE/BSE endpoints, Screener.in, FRED, RSS feeds) and validates the returned payload against per-source invariants before the agent ever sees the data. Invariants are defined as a dict of callables per data source, e.g. for yfinance: RSI must be 0–100, MACD histogram must be finite, price > 0, volume > 0; for NSE FII flows: net value must be a finite float not equal to exactly 0.0 when market was open; for Screener.in PE: PE > 0 and < 10000. If any invariant fails, the decorator raises a `SilentAPIFailure` exception with the violated invariant name and raw value, which the calling agent catches to return `{signal: 'HOLD', score: 50, detail: {'error': 'invariant_violation', 'invariant': <name>, 'raw_value': <val>}, ...}` rather than propagating a plausible-but-wrong result to the LangGraph orchestrator. This directly applies the SilentGuard paper's core finding that enforcement (not warnings) is what cuts wrong answers from ~70% to <2%.
