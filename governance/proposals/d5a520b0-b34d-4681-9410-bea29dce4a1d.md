## Abstract

arXiv:2611.26649v1 Announce Type: new 
Abstract: Large language models embedded in financial workflows fail most dangerously by emitting confident, well-formatted but wrong numbers with no signal distinguishing them from correct ones. We argue that the central deployment problem is governability: a system must determine when a question supports a numeric answer and when it should instead clarify, intercept, or refuse. We present VerifiQuant, a governance-by-execution framework that packages financial logic into inference contracts and evaluates each query through an executable diagnostic funnel before deterministic computation. This separation makes computation, clarification, and refusal structured and auditable while keeping financial arithmetic outside the language model. Against matche

## Proposed Change

Add an InferenceContractRegistry to governance/hallucination_detector.py that defines executable contracts for each numeric claim type produced by agents (e.g., RSI bounds 0-100, PE ratio > 0, ROCE percentage, FII flow sign-consistency with signal). Before the weekly hallucination audit runs, introduce a pre-synthesis 'diagnostic funnel' function validate_agent_numerics(agent_output: dict) -> ContractResult that checks each numeric field in agent detail dicts against its declared contract bounds and type constraints deterministically in Python—without asking the LLM—and returns a structured refusal/flag if no applicable contract matches the field rather than passing the value downstream. Agents whose outputs fail contract validation are quarantined and replaced with a HOLD/50 safe default before Claude Sonnet synthesis, with a structured audit log entry written to Supabase. This keeps financial arithmetic validation outside the LLM entirely, matching VerifiQuant's core principle that numeric governance must be deterministic and auditable.
