## Abstract

arXiv:2605.03310v1 Announce Type: cross 
Abstract: Multi-agent LLM systems fail in production at rates between 41% and 87%, mostly due to coordination defects rather than base-model capability. Existing responses split between cataloguing failure modes empirically and shipping declarative orchestration frameworks as engineering tools; neither delivers a principled mapping from coordination configuration to predictable failure-mode signature. We argue that coordination should be treated as a configurable architectural layer, separable from agent logic and from information access, enabling architectural reasoning rather than only engineering productivity.

## Proposed Change

Add a new orchestrator/coordination_config.py module that defines five coordination modes (sequential, parallel, hierarchical, debate, ensemble) as architectural configurations. Modify orchestrator/synthesis.py to accept a coordination_mode parameter, route agent calls accordingly, and log per-mode Brier score decomposition (calibration vs. discrimination) by comparing daily predictions against next-day price moves. This separates coordination logic from agent implementation, enabling A/B testing of coordination architectures against predictable failure signatures.
