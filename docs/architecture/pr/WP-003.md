## WP-003 — Freeze agent weights to equal in one config file (ADR-003)

### Why
Production composite weights came from six stale `agent_performance` rows: technical carried ~0.2% of
the composite and institutional ~22% (`scheduler/orchestrator.py` `_normalise_weights` + `load_weights_node`).
Per ADR-003, weights are equal until ledger evidence clears the ADR-006 promotion rule.

### What changed
- **New `data/decision_config.py`** — the only place agent weights live: `AGENT_NAMES`,
  `AGENT_WEIGHTS_MODE="equal"`, `REGIME_MULTIPLIERS_ENABLED=False`, `LEGACY_DISCOVERY_WEIGHTS`
  (kept only for rollback), helpers `equal_weights()`, `discovery_weights()`, `describe_weights()`.
- **`scheduler/orchestrator.py`**
  - `AGENT_NAMES` now comes from `decision_config`.
  - `load_weights_node`: in equal mode, returns 1/7 each and does **not** read `agent_performance`;
    logs `Agent weights: equal (7 × 0.1429)`. Accuracy mode is preserved for rollback.
  - `_composite_score`: regime multipliers applied only when `REGIME_MULTIPLIERS_ENABLED`; the
    failure path now logs at WARNING instead of DEBUG.
  - Regime log line now states whether multipliers are ON/OFF.
- **`agents/discovery_screener.py`**: removed its own `_AGENT_WEIGHTS` table (0.20/0.25/0.10/…);
  `_composite_score` now uses `decision_config.discovery_weights()` (equal).
- **`agents/outcome_tracker.py`**: the P6-D-8 sentiment flag wrote `accuracy_90d` as a fraction
  (`accuracy_30d / 100`); now writes the percentage like every other writer.
- **Tests**: new `tests/test_decision_config.py` (equal weights whatever `agent_performance` holds;
  `agent_performance` not read; rollback path; AST scan that fails if any runtime module other than
  `decision_config` defines an agent-weight table, plus a self-test of the scan), new
  `tests/test_orchestrator.py` (equal-weight composite, regime multipliers gated on/off, NO_DATA
  exclusion). `tests/test_discovery_screener.py`: the test asserting fundamental > sentiment weight is
  replaced by one asserting equal weighting.

### Risk (medium)
- **Composite scores shift** on the first run for both pipelines — technical returns to full weight.
- **Discovery signal score distribution shifts.** `metadata.signal_score` drives selection
  (≥65 / ≥75), position sizing and the calibration band in `agents/call_calibration.py`. The bands
  were fitted on scores from the old fixed weights, so calibrated confidence for new calls is read
  from bands built on a slightly different score definition until new outcomes accumulate. The
  pass rate through the 65/75 thresholds may move either way. Worth watching the first week of
  discovery runs.
- Regime multipliers are now off; regime is still loaded and logged.

### Rollback
Set `AGENT_WEIGHTS_MODE = "accuracy"` (and/or `REGIME_MULTIPLIERS_ENABLED = True`) in
`data/decision_config.py`, or revert the PR. Accuracy mode restores the old orchestrator behaviour
and the legacy fixed discovery weights.
