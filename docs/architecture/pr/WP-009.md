## WP-009 — Add an exception-policy test with a shrinking allowlist (ADR-005)

### Why
Five production outages ran for weeks to months unseen because a broad `except` swallowed the
error. Examples: a tz-naive date subtraction returned `None` at DEBUG and froze the Performance tab
for about 3 months; writes to non-existent columns were logged only at DEBUG or WARNING. This is
mechanism 4 of ADR-005: no *new* silent handler can be added, and the existing ones can only go down.

### What changed (only `tests/`)
- **New `tests/test_exception_policy.py`**: walks the AST of every `.py` file under `agents/`, `data/`, `scheduler/`, `governance/` and `api/`.
  - It flags a handler that catches everything (`except Exception`, `except BaseException`, a bare `except:`, or a tuple containing one), neither re-raises nor logs at WARNING+, and either:
    - only passes, continues, breaks, or returns `None` or an empty literal (`[]`, `{}`, `()`, `""`, `0`, `False`, `set()`…); or
    - logs only at debug/info.
  - Each site is identified as `path::function::ordinal`, where the function name is qualified (`Class.method`, `outer.inner`) and the ordinal is the position among flagged handlers in that function. Line shifts therefore don't break the list.
  - `test_no_new_silent_exception_handlers` fails on any flagged site not on the allowlist.
  - `test_allowlist_only_shrinks` fails on any listed site that no longer exists, so a fix forces its line out.
  - The current count prints with `-s`; `python tests/test_exception_policy.py` prints just the number, for the evidence pack.
  - Plus 5 classifier tests (the classic swallow, debug/info-only logging, loud or narrow handlers not flagged, site naming, and the injected-swallow acceptance check).
- **New `tests/exception_allowlist.txt`**: the **173** silent handlers in today's tree, generated by `python tests/test_exception_policy.py --write`. The biggest groups are `api/main.py` 21, `data/options_fetcher.py` 11, `data/fetchers.py` 11 and `governance/hallucination_detector.py` 10. Spot-checked samples are genuine swallows, e.g. `portfolio_monitor._alert_exists` logs at DEBUG and returns `False`, so a failed dedup check silently lets duplicate alerts through.

### Risk
Low. Test-only. A future PR that adds a silent handler will fail CI with the site named.

### Rollback
Delete the test and the allowlist.
