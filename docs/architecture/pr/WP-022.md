## WP-022 — Label the backtest honestly in the API (ADR-006)

### Why
The backtest that reports 62–66 % hit rates replays **one technical rule** (RSI + EMA200 + MACD), not
the live multi-agent system, on a **survivorship-biased** universe (today's NIFTY 500 applied back to
2020). Its "Max DD" is the worst single trade and its "Sharpe" is mean/std of per-trade alpha, not
annualised. ADR-006 says it must stop being cited as system validation.

### What changed
- **`api/main.py` — `GET /api/backtest/summary`**
  - The response now carries `strategy: "technical_rule_only"`, `survivorship_bias: true` and a
    plain-English `caveat`.
  - Each row adds `worstTrade` (= `max_drawdown`) and `alphaMeanOverStd` (= `sharpe_ratio`). The
    original keys stay for one release because the dashboard reads them.
  - The endpoint docstring explains all this. **No database column is renamed.**
- **`agents/backtester.py`**
  - A "What this backtest is NOT" section in the module docstring.
  - Corrected comments on the two metrics.
  - `BACKTEST_STRATEGY`, `SURVIVORSHIP_BIAS` and `BACKTEST_CAVEAT` constants, which the API returns.
- **`dashboard/src/App.jsx`** (outside `touches`; the redesign it was waiting on merged
  2026-11-15)
  - The Backtest panel's "Avg Sharpe" / "Avg Max DD" tiles become "Avg alpha ÷ σ (per trade)" /
    "Avg worst single trade".
  - The column headers become "Alpha÷σ" / "Worst trade".
  - The API's caveat is shown under the table. Without this, the honest labels would have stopped
    at the API.
  - `CI=true npx react-scripts build` is clean, and the dashboard tests pass (4).
