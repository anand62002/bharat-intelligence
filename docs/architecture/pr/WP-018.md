## WP-018 — Move every number out of the synthesis prompt into code (ADR-001)

### Why
The synthesis prompt asked the LLM for the action, confidence, upside confidence, target, upside and
danger, with a table mapping composite score to a "confidence range". Every number was model
opinion. "Confidence" changed meaning with each model upgrade, an explicit JSON null once crashed
the run, and a truncated reply lost the symbol.

### What changed
- **New `scheduler/decision.py`**
  - `decide(symbol, agent_results, composite, price, calibration)` computes every number in code:
    - **Action:** the composite rule (BUY ≥ 65, HOLD ≥ 45, AVOID ≤ 30, else SELL; provisional,
      see below), then `_apply_consensus_gate`. The gate now moves
      only the action, never confidence.
    - **Confidence:** the calibrated beat-Nifty rate for the composite's band.
    - **Entry:** price − 1×ATR14 to price.
    - **Stop:** the technical agent's `atr_stoploss` (2×ATR).
    - **Target:** the larger of the fundamental and technical upside, **capped at 100 %** as
      discovery does. There is no entry or target on SELL/AVOID.
    - **Horizon:** 90 days.
    - **Danger:** the fundamental agent's figure, else the stop distance.
    - Each decision carries a `decision_basis` audit record: rule action, gate note, whether
      confidence is calibrated or "no track record", band n, upside source, raw valuation gap
      and whether it was capped.
  - `render_prompt()` gives the decision to the LLM as fixed facts. `merge_narrative()` takes
    **only** bull_case, bear_case, synthesis, headline and market_constraints from the reply;
    any numeric or action field it returns is ignored and logged. `veto: true` can only turn
    **BUY into HOLD** and is recorded with its reason. `fallback_narrative()` writes the text
    from `agents/rationale.py` when the LLM fails.
- **`prompts/orchestrator_synthesis.txt`** is rewritten as narrative only: the decision goes in as
  inputs, the output schema has no numbers, the calibration table is gone and the veto is added.
  `upside_confidence` occurs 0 times. The old prompt is kept as `orchestrator_synthesis_llm.txt`
  for rollback.
- **`scheduler/orchestrator.py`**
  - `synthesise_node` loads the composite calibration once per run and calls `decide()` before
    the LLM.
  - All three failure paths (overloaded, unparseable, no client) publish the decision with the
    templated narrative. Overloaded and unparseable still record `SYNTHESIS_FALLBACK` in the
    run's errors, so **a synthesis failure costs the prose, never the recommendation**.
  - The consensus gate isn't applied a second time.
  - `_build_recommendation` no longer backfills a target or stop that the decision left empty
    on purpose.
  - `decision_basis` is saved to `recommendations.metadata.decision`.
  - Unchanged: the P7-C data-density caps and the earnings guard still lower confidence
    afterwards, and the judge panel still runs.
- **`agents/call_calibration.py`**: `build_calibration` takes an optional `score_fn` and bands
  (discovery's behaviour is unchanged). New `load_composite_calibration()` builds the
  calibration from resolved **portfolio** outcomes by composite band. Under 30 resolved calls
  it returns the neutral **50 %**, labelled `no_track_record`. That's today's honest answer,
  since the portfolio pipeline has only published since 2026-11-13.
- **`data/decision_config.py`**: `DECISION_SOURCE = "code"` (rollback: `"llm"`), the action
  thresholds, `COMPOSITE_BANDS`, `UPSIDE_CAP_PCT`, `DECISION_HORIZON_DAYS`, `ENTRY_ATR_MULTIPLE`.
- **`scripts/test_synthesis.py`** checks the smaller contract through the same
  decide/render/merge functions the orchestrator uses.

### What changes for you
- **Confidence on portfolio recommendations now reads 50 %** (no track record) instead of an
  LLM figure in the 60s–80s. It moves to calibrated band rates once 30 portfolio calls have
  resolved at 90 days. That's the ADR-006 product language: no measured edge yet, shown
  honestly.
- **Actions follow the composite rule plus the consensus gate**, and the LLM can only hold a
  BUY back. Expect fewer BUYs than the LLM used to give.
- **Targets come from the agents' valuation gap, capped at 100 %.** Stops always equal the
  2×ATR floor.

### Risk
High, as rated: this changes every published number. The judge panel still gates publication
on the narrative. `decision_basis` records each number's origin, and vetoes are recorded so
their value can be measured after 90 days (ADR-001).

### Rollback
Set `DECISION_SOURCE = "llm"` in `data/decision_config.py`. That restores the old prompt and
LLM-number path (covered by `test_rollback_to_llm_numbers`).

### Action thresholds re-centred (owner decision 2026-11-16)
The P1-D thresholds (75 / 58 / 30) were set for the old accuracy-weighted composite. Since WP-003
(equal weights), composites cluster around 44–64, so 75/58 would have published SELL on 22–23 of
24 holdings every day. The owner chose to **re-centre to BUY ≥ 65, HOLD ≥ 45, AVOID ≤ 30**,
marked PROVISIONAL in `data/decision_config.py` for ADR-006 to revisit once the ledger has
≥300 labelled rows across ≥8 weeks. Replayed on the last two days of published portfolio calls:

| Day | LLM actions (published) | Code rule 75/58/30 (rejected) | Code rule 65/45/30 (shipped) |
|---|---|---|---|
| 2026-11-15 | HOLD 17, SELL 3, AVOID 4 | SELL 23, HOLD 1 | HOLD 22, SELL 2 |
| 2026-11-16 | HOLD 18, SELL 2, AVOID 4 | SELL 22, HOLD 2 | HOLD 24 |

The code rule produces no AVOID calls on these days (no composite ≤ 30), whereas the LLM gave
AVOID to 4. Those holdings now read HOLD unless the composite or the consensus gate says otherwise.

### Fable review (2026-11-16): REQUEST CHANGES → fixed
A read-only Fable review against ADR-001/ADR-006 found the core sound: the LLM can't set a
number or upgrade an action, and the `llm` rollback is faithful. It also found defects; all are
fixed, each with a test:

| # | Finding | Fix |
|---|---|---|
| 1 | Truncation, refusal or any non-529 API error (401, 400, timeout) still dropped the symbol, with no `SYNTHESIS_FALLBACK` | In code mode every model error publishes the decision with the templated narrative and records `SYNTHESIS_FALLBACK (<error>)` |
| 2 | Judges could suppress a code decision, even one carrying the template | Judges never score the template. In code mode SUPPRESSED replaces the narrative with the template and **publishes** (logged for review as before; ledger row PROMOTED with `gate_status: SUPPRESSED`). The legacy path still drops it |
| 3 | `synthesis` returned as a list or dict raised `TypeError` and lost the symbol | Narrative fields are coerced to text or lists; the parse handler also catches TypeError/AttributeError |
| 4 | Post-decision tweaks moved "confidence": earnings guard −20, fact-checker −15 per contradicted claim (driven by LLM prose), P7-C caps | In code mode these record flags in `decision_basis` (`earnings_risk`, `data_density`) and `gov_check.confidence_delta_not_applied`; confidence stays the calibrated rate. Warning texts are kept; "Confidence capped" is only said when it is |
| 5 | Every code BUY sized at 0 % (confidence 50 < QUARTER's 55) | Interim until WP-019: sizing uses the decision's composite |
| 6 | A veto left the LLM's headline saying "BUY" | The headline prefix `ACTION: SYMBOL —` is built in code after the veto; any action the LLM led with is stripped |
| 7 | Confidence was inverted for SELL/AVOID | SELL/AVOID confidence = P(underperform) = 100 − band beat rate; `confidence_meaning` is recorded |
| 8 | Calibration mixed accuracy-weighted composites into equal-weight bands | Only outcomes from `EQUAL_WEIGHTS_SINCE` (2026-11-15) count |
| 9 | `danger_confidence` was on a 0–1 scale; a danger of 0.0 blocked the fallback; a stale stop could sit above entry; `"null"` counted as a veto | Scaled ×100; `if not danger`; stop rebuilt from this price (or dropped) and noted; strict veto parse |
| 10 | Prompt asked for a position tier and hard-coded "2× ATR" even with no stop | Position tier removed (sizing is code); the stop line is rendered in code |
| opt | Band edge 30.01 mislabelled 30.00–30.01; vetoes weren't logged for scoring | `math.nextafter` edge; veto and narrative source written to the candidates row's `features` |
