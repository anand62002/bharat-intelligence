## WP-008 — Remove production credentials from CI test runs (ADR-005)

### Why
`ci.yml` handed the production Supabase service-role key, the Anthropic key and a GitHub PAT to every
pull-request test run. Any test that forgot a mock therefore read or wrote production data, or paid
for live LLM calls. That is not hypothetical: this work found test fixture rows in production (below).

### What changed
- **`.github/workflows/ci.yml`**
  - Secret references are replaced by fixed dummy values:
    - `SUPABASE_URL=http://127.0.0.1:9` (a closed port, so an unmocked call fails fast).
    - A JWT-shaped dummy `SUPABASE_SERVICE_KEY`. supabase-py validates the key format when `api/main.py` builds its client at import; the payload is `{"role":"ci-dummy","iss":"ci-not-a-real-key"}`.
    - Dummy Anthropic and OpenAI keys.
  - `GH_PAT` / `GITHUB_TOKEN_GH` dropped: no code reads it.
  - Pytest now runs with `-m "not integration"`.
  - The only secret left is the built-in `GITHUB_TOKEN` for the results comment.
- **`tests/conftest.py`: autouse `_no_live_clients` guard.** For every test not marked `integration`, it replaces `supabase.create_client`, `anthropic.Anthropic` / `AsyncAnthropic`, `openai.OpenAI` / `AsyncOpenAI` (and `api.main.create_client`, imported at module level) with a blocker.
  - The blocker raises, and also records the call and where it came from (`file:line`).
  - The test then fails at teardown. This matters because most of this code catches client errors and degrades gracefully, so a bare raise would be swallowed and the test would pass.
  - Mocks that tests apply themselves take precedence.
- **Tests fixed** (everything the guard caught):

  | File | What it reached | Fix |
  |---|---|---|
  | `test_fundamental.py` (65 tests) | `data/forward_estimates.py` Supabase cache (read **and upsert**) + `agent_performance` write | autouse stub for `forward_estimates._supabase_client` and `_write_agent_performance` |
  | `test_historical_rag.py` (6) | `agent_performance` write | autouse stub for `_write_agent_performance` |
  | `test_discovery_screener.py::TestRunDiscovery` (3) | **live Anthropic judge panel** (incl. Opus) for CRITICAL candidates on every local run | class fixture removes `ANTHROPIC_API_KEY`; the check is skipped and the tier is kept, which is what the tests assert |
  | `test_hallucination_detector.py::test_no_client_returns_empty_dict` | production `agent_performance` (the test reported as failing in every full run this week) | patches `_supabase` to `None` |
  | `test_research_agent.py` (5, pre-existing failures) | fixtures hard-coded to 22 Apr 2026, outside the agent's 7-day lookback | fixture dates are now yesterday |

### Production data written by tests (not changed by this PR)
`forward_estimates_cache` holds three rows written by local test runs on 2026-11-14 at 09:39–09:40 UTC:
`TEST`, `TEST_BANK`, `TEST_ENERGY`. Real symbols never match these, so they're harmless, but they're
junk. To remove them (owner's call):
```sql
delete from forward_estimates_cache where symbol in ('TEST', 'TEST_BANK', 'TEST_ENERGY');
```

Before this PR, the same CI-style run gave 5 failed and 75 errors. With real credentials the suite took
~17 min; without them it takes ~1.5–2 min, because tests had been waiting on live services.

### Repository secrets the maintainer can now delete
`ci.yml` no longer reads them: **`SUPABASE_SERVICE_KEY`**, **`ANTHROPIC_API_KEY`** and **`SUPABASE_URL`**
(GitHub → Settings → Secrets and variables → Actions). Checked: `deploy.yml` and
`governance_rollback.yml` don't use them either. **Keep `GH_PAT`**: `governance_rollback.yml` still uses
it (lines 31 and 117). Keep `TELEGRAM_*` too.

### Risk
Medium.
- A future test that forgets a mock now fails CI instead of quietly touching production. That's the intent, and the failure message names the file and line that built the client.
- Integration tests no longer run in CI. Run them by hand with `pytest -m integration`.
