## WP-017 — Fit a shadow probability model on the ledger (ADR-006)

### Why
Discovery's calibration bands (41.6 / 53.3 / 43.9 / 37.3 % on n = 13–38) can't separate good calls
from bad. The candidates ledger (WP-012..014) gives roughly ten times more labelled rows to learn
from. This package builds the model and its honest evaluation. It changes nothing in production.

### What changed
- **New `agents/shadow_model.py`** (numpy only, no new dependency)
  - **Features:** a fixed vector of 14. Seven come from the pre-screen (RSI, above EMA200,
    PE ÷ sector PE, revenue growth, institutional %, filters passed, DVM). Seven are the agents'
    scores. A missing value is imputed with the training median, and a separate missing-indicator
    column records it. Missing never silently becomes 0.
  - **Model:** L2 logistic regression by Newton/IRLS (intercept unpenalised), then isotonic
    calibration (pool-adjacent-violators) on the later 25 % of the training window.
  - **Walk-forward by week:** each test fold is one calendar week. Training uses only rows whose
    label already existed before that week (`run_date + horizon < week start`), so no future
    outcome leaks in and no row is in both sets.
  - **Metrics:** beat-Nifty rate by score quintile; Brier score against the base-rate baseline,
    with the difference and its interval; one call per symbol per 30 days (ADR-006 primary
    metric). 90 % intervals use a cluster-robust ratio estimator on **weekly clusters**.
  - **Incumbents get the same treatment:** live `signal_score`, the equal-weight agent composite,
    and pre-screen pass vs fail (with the difference and its interval).
  - **Promotion checklist** per ADR-006: top-quintile lower bound > 50 %, beats signal_score's
    top quintile on the same rows, Brier below baseline. It is reported only; nothing is promoted.
  - **Refusal:** below **300 labelled rows or 8 distinct weeks**, the result is
    `insufficient data: N rows, W weeks` and no report is produced.
- **New `scripts/evaluate_shadow_model.py`**: reads labelled ledger rows (read-only), prints
  markdown for t+30 (marked provisional) and t+90, and writes nothing.

### When it will say something
The 8-week rule needs 8 weeks of labelled rows, and t+30 labels arrive 30 days after a row is
written. The first meaningful t+30 report is expected around **early February 2027**, and t+90
about two months after that. Until then it prints the refusal line, which is the point.
