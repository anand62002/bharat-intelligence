## WP-015 — Store the gate score for every symbol, honestly named (ADR-004)

### Why
The validation metric called "kappa" is mean judge quality × raw agreement
(`synthesis_validator.py`, `_compute_dimension_kappa`); it has no chance correction, so it is
not a kappa statistic. No outcome row carried it, so nobody could test whether it ranks outcomes.

### What changed
- **`scheduler/synthesis_validator.py`**: `ValidationOutcome.to_dict()` now emits `gate_score`
  alongside `aggregate_kappa`, with the same value. `aggregate_kappa` stays for one release so
  existing readers don't break. The module, field and per-rubric docstrings now say what it is:
  quality × agreement, a gate score, not a kappa. **No thresholds and no suppression logic changed**,
  and a test pins `KAPPA_SUPPRESS = 0.30` and `KAPPA_SUPPRESS_DISCOVERY = 0.35`.
- **`scheduler/orchestrator.py`**: every holding that reaches the gate gets a `candidates` row
  (`source='portfolio'`), **published or suppressed**. The row is written before the suppression
  `continue`.
  - Columns: `gate_score`; `signal_score` = composite; `stage` PROMOTED (published) or DEEP
    (suppressed); price, yf_symbol, agent signals, data quality.
  - `features` holds the gate status, per-rubric quality, agreement and gate, the action, and
    whether it was published.
  - One batch upsert per run with the Nifty fetched once. Dry and on-demand runs write nothing.
  - A ledger failure is a WARNING plus a run error, never a crash.
- **`agents/discovery_screener.py`**: the CRITICAL-path discovery validation score is written to
  the symbol's deep row as `gate_score`, including when the gate suppresses or demotes it.
- **`data/candidate_ledger.py`**: `deep_row()` always carries `gate_score` (None when no gate
  ran), so every row in a batch has the same keys.
- **`api/main.py`**: `_transform_recommendation` adds `gateScore`. It reads `gov_check.validation`
  `gate_score` and falls back to `aggregate_kappa` for rows written before this change.
  `govCheck` is unchanged.
