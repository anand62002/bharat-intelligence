## WP-023 — Report ADR signals and ledger evaluation in the evidence pack (ADR-006)

### Why
The evidence pack labelled discovery's `daily_runs` rows as "orchestrator runs" and reported
suppression as a share of saved rows. It didn't carry the signals each ADR names (job ledger,
invariants, schema contract, candidate ledger, shadow model).

### What changed — `scripts/build_architect_pack.py`
- **Pipeline runs by pipeline**
  - All-time counts per `daily_runs.pipeline`, with **orchestrator and discovery on separate
    lines**. They match `select pipeline, count(*) from daily_runs group by 1` exactly (checked
    against production).
  - Last-30-day status and duration for each.
  - Suppression and fallback reported **as a share of symbols analysed**, from
    `details.reasons`.
  - Portfolio-pipeline rows by kind (recommendation vs HOLDING_REVIEW) and action.
- **Job ledger** (new)
  - **Coverage**: jobs due versus rows logged, per day, naming the missing jobs. "Due" comes from
    the real APScheduler triggers (`worker.build_scheduler()`). Counting starts on the ledger's
    first day, so pre-WP-005 days don't read as missing.
  - JOB_INVARIANT breaches in 30 days; the exception allowlist count; the WP-007 schema-contract
    result; median LLM tokens per run per pipeline.
- **Candidate ledger** (new)
  - Rows by source and stage; labelled t+30 and t+90 counts; share by data quality.
  - **Pre-screen pass vs fail** and **gate score top vs bottom half**, as 30-day beat-Nifty rates
    with weekly-cluster intervals. This is WP-020's precondition, shown where the reviewer will
    see it.
  - The **WP-017 shadow-model report**, or its honest refusal line.
- **Paper book split by rec source** (discovery / portfolio / holding_review), with win rates
  and beat-Nifty rates, plus the position-size labels from WP-019.
- **Every rate carries its n and a 90 % interval**: Wilson for counts, weekly clusters for
  ledger rows.
- **Findings** are computed (is the portfolio pipeline publishing in the last 7 days?) instead
  of historical prose. The backtest section uses WP-022's caveat.

### Fixed while building it: `portfolio_risk` never left a ledger row
The new coverage table showed `portfolio_risk` missing on every day since the ledger started.
Its result carries a correlation matrix with NaN values (517 on a probe run). `data/run_log.py`'s
`_jsonable()` round-tripped through `json.dumps(default=str)`, which keeps NaN and turns numpy
numbers into strings. The HTTP client then refused the insert ("Out of range float values are
not JSON compliant"), and the job's row was lost with only a warning.

The new `_json_safe()` turns NaN and ±inf into null, numpy scalars into plain Python numbers,
and anything else into a string, for **every** job's output. A regression test covers it
(`tests/test_run_log.py`).
