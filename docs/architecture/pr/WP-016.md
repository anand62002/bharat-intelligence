## WP-016 — Typed agent results with contract tests (ADR-005), and the gaps they found

### Why
`target_updater` read warren_bot's `intrinsic_value`, a key the agent never emits, so target
extension silently never ran for months. The tests mocked the same wrong key.

### Commit 1: the contract (`475d00d`)
- **`agents/contracts.py`**
  - A `TypedDict` per agent listing the keys other modules read.
  - **`CONSUMED_KEYS`**: agent → consumer → keys, with dotted paths for nested reads. Built
    from an AST scan of scheduler/, agents/, api/, governance/ and data/ for reads on agent
    results, plus functions that take a result as a parameter (multibagger `deep_check`,
    `score` and `_eps_growth`; target updater `_intrinsic`).
  - `PATH_DEPENDENT`: keys present only on some paths, each with a reason. `KNOWN_MISSING`:
    a shrink-only allowlist.
- **`tests/fixtures/agent_outputs/*.json`**: one **real** output per agent (TITAN, 2026-11-16),
  recorded by the new `scripts/record_agent_fixtures.py`. It runs each agent's real `analyse()`
  with Supabase and LLM keys removed, so nothing writes to the database and no paid model is
  called. Market-data reads are live, so this is not a mocked-network recording.
- **`tests/test_agent_contracts.py`**: every consumed key must exist in the producing agent's
  recorded output.

### Commit 2: fixing what the check found (owner asked for the fixes in this package)
The first run found consumers reading keys that **no agent emits**. Each was a silent decision-path bug:

| Gap | Effect in production | Fix |
|---|---|---|
| fundamental `detail.valuation.current_price` | The synthesis prompt said **"Current price: ₹N/A" for every holding**, and the ATR entry floor (P7-D) was "N/A" too | `orchestrator._current_price()`: fundamental `raw_metrics.current_price`, then technical `indicators.current_price`; used for the prompt, the ATR entry zone, upside derivation and the ledger row |
| fundamental `detail.valuation.{entry_low,entry_high,target}`, technical `detail.targets.{target,stoploss}` | A level the synthesis left null stayed null | Target falls back to technical `target_price_used` (the basis of its upside_pct). Stoploss falls back to `atr_stoploss`. There's no entry fallback, since no agent produces an entry zone |
| `years_available` (fundamental detail / warren_bot) | **P7-C data-density cap (confidence ≤ 60 under 5 years of history) never fired.** The prompt said "data years: unknown" | warren_bot emits `years_available`. The orchestrator reads it from warren_bot only |
| warren_bot `error` | The failure fallback never set it, so discovery sizing, the target updater and multibagger `deep_check` treated a **crashed warren_bot as a valid result** | The fallback sets `error` (and `years_available: None`) |
| `save_recs_node` metadata | It read ATR, data years and data quality from the stored compact `agent_signals` (signal/score/weight/reason only), so **those metadata fields were never saved** | `_build_recommendation` computes `decision_meta` from the raw results; save copies it |
| sentiment `dominant_event_class` | Sentiment-validation rows always had `event_class` NULL | Sentiment emits it (most frequent non-ROUTINE class), and the stored sentiment signal keeps it |
| fundamental `detail.data_quality` | Harmless: it fell through to the top-level key | The dead read was removed |

`KNOWN_MISSING` is now **empty**, and a test keeps it that way. The warren_bot and sentiment
fixtures were re-recorded. Two re-recording attempts hit rate-limited sources (NO_DATA or
INSUFFICIENT_DATA), so the unaffected agents keep their first, complete recording. The script
now records a subset (`... TITAN sentiment`) and warns about degraded runs.
