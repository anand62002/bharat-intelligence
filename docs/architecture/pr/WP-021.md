## WP-021 — Publish a daily holdings review from the portfolio pipeline (ADR-007)

### Why
The 06:00 pipeline analyses your open holdings, but it published BUY-style calls with an entry zone.
That's the wrong question for a stock you already own: you need keep, trim or sell. A rule for that
already existed, `agents/target_updater.py::exit_signal()`.

### What changed
- **`scheduler/decision.py`**
  - `review_holding(holding, agent_results, fair_value, *, price, rule_action)` returns:
    - **review_action**: EXIT / BOOK_PARTIAL / TRAIL / REVIEW / HOLD, from `exit_signal()` with
      today's agent price;
    - **thesis_status**: INTACT / WEAKENED / BROKEN / UNKNOWN;
    - the reason; the stop and target from the holding.
  - Thesis rule: `discovery_rescorer.thesis_check()` (the same test the discovery re-check
    applies). WEAKENED if the stock no longer passes; BROKEN if it also fails the composite rule
    (SELL/AVOID). A BROKEN thesis turns a HOLD into REVIEW.
  - The `action` column maps EXIT → SELL and everything else → HOLD. **A review is never a BUY.**
- **`scheduler/orchestrator.py` — `save_recs_node`** (it runs only in the full 06:00 graph, so
  **`POST /api/analyse` is unchanged**). With open holdings:
  - every rec for a held stock becomes its review, with `metadata.kind = "HOLDING_REVIEW"`, the
    review fields, no entry zone, **stop/target read from `portfolio_holdings` (not written)**,
    no sizing and `valid_till` = tomorrow;
  - a holding the pipeline produced nothing for (its agents failed) still gets a review from the
    exit rule alone, so **a holding always has a review**;
  - before insert, each holding's previous live review is retired (`valid_till` = yesterday), so
    **one live review per holding**;
  - recs for non-held symbols (WATCHLIST) are saved as before;
  - reviews seed their outcome row at the **price on the review date**, so EXIT advice can be
    scored later (ADR-007).
- **`api/main.py`**
  - `GET /api/portfolio` adds `reviewAction`, `thesisStatus`, `reviewReason` and `reviewDate` from
    the live review. `exitSignal` stays.
  - `GET /api/recommendations` excludes reviews by default (`?include_reviews=true` to include them).
    It also drops older non-discovery recs for symbols that now have a live review. Otherwise a
    held stock's pre-review BUY call would resurface as its newest row.
- **`scheduler/invariants.py`**: the orchestrator invariant now also checks **live reviews =
  open holdings** (the 19:00 watchdog raises `JOB_INVARIANT` otherwise).
- **`agents/paper_portfolio.py`**: unchanged. Its WP-004 `_drop_holding_reviews` filter already
  keeps reviews out of the paper book (tested again here).

### What changes on the dashboard
- **Portfolio Recs tab, "My holdings":** held stocks no longer appear there. Their answer is the
  review on the Portfolio tab, as ADR-007 intends ("one answer per holding").
- **Portfolio tab:** shows `exitSignal` as today. The API now also returns `reviewAction` and
  `thesisStatus`, but showing thesis status needs a small dashboard change, which is not in this
  package.

### Risk
High, as rated: the pipeline's published output changes shape. Mitigations:
- reviews can never be BUY or sized;
- every holding always gets a review;
- the invariant watches the count;
- `/api/analyse` is untouched.

### Rollback
Revert the PR. To hide reviews already written:
`update recommendations set valid_till = current_date - 1 where metadata->>'kind' = 'HOLDING_REVIEW';`
