## WP-001 — Confirm the portfolio pipeline publishes on the next run

### Why
The fix in `bf5d3fa` (schema-drift-tolerant insert + honest run log) had never been confirmed in
production. Before it, `daily_runs` had no orchestrator row and every non-discovery rec ever saved
was SUPPRESSED. This adds a read-only check that answers "did the 06:00 run publish?" for any date,
following `docs/architecture/REVIEW.md` §3.

### What changed
- **New `scripts/verify_pipeline_publish.py`** (SELECTs only). `--date YYYY-MM-DD` (default today).
  Prints the orchestrator's `daily_runs` row (status, symbols_processed, errors, `details.reasons`,
  `details.errors`), counts of `is_discovery=false` recommendations by action, and a verdict:
  - `PUBLISHED`: at least one non-SUPPRESSED rec.
  - `SCHEMA_DRIFT_ONLY`: published, and the only run errors are `SCHEMA_DRIFT` (a migration is pending).
  - `ALL_SUPPRESSED`: rows exist but all are SUPPRESSED, or the run status says so.
  - `NO_OUTPUT`: the run logged a row but saved nothing.
  - `NO_RUN`: no run row and no recs.

  Exit 0 only for PUBLISHED / SCHEMA_DRIFT_ONLY. If `daily_runs` has no `pipeline` column yet, it
  falls back to recognising the orchestrator row by status values that only the orchestrator writes.
- **New `tests/test_verify_pipeline_publish.py`** (20 tests, no live DB): each verdict, the exit-code
  rule, row picking with and without the `pipeline` column, `main()` against a mocked client, and an
  assertion that the script never calls insert/update/upsert/delete.

### Findings
- **REVIEW.md §3 hypothesis confirmed.** 24 of 24 holdings published on each of the two runs since
  `bf5d3fa`, and the judges suppressed none. The missing column was the blocker, not the gate.
- **WP-002 is already done.** Production `recommendations` has `danger_drop_pct` (values written on
  2026-11-14), and `daily_runs` has `pipeline`/`details`. No SCHEMA_DRIFT errors appear.
- **No BUYs yet.** Both runs produced only HOLD/AVOID/SELL, so the REVIEW §3 concern (holdings BUYs
  entering the 90-day paper book) hasn't happened yet. WP-004/WP-021 still apply.

### Risk
Low. It's a new read-only script plus tests, and no runtime code imports it.
